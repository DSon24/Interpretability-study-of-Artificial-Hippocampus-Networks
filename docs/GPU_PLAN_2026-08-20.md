### Five things that are drifting, in order of how much they matter

**A1. Notebook 04 will crash on its own prerequisite check. (blocker, 2-minute fix)**

Cell 4 does:

```python
try:
    lens = ai.JacobianLens.load(EXP["jlens_path"], ...)
    v = ai.load_json("02_table3_jlens_validation.json")
    assert v.get("TABLE_3_PASSED"), "Table 3 has not passed — see notebook 02"
```

`TABLE_3_PASSED` is **false** (checks 2 and 3 fail). The `except` catches `FileNotFoundError`

label the figures. The code and the plan disagree. Fix: downgrade the assert to a warning

### Step 1 — `04_niah_retention.ipynb` on GDN 3B  ·  ~1.0 h

The critical-path run. Everything downstream — Tables 4, 6, 7, 8 and Figures 4–7 — comes out
of this one sweep, and it is also the evidence Gautam needs for the J-lens go/no-go.

Run with `USE_JLENS=True`. Watch these as they come out:

- **C1 (zero-state)** — target inside the top decile of the 151,936-token vocabulary. If it
  fails, stop: the lens is reading the backbone, not the memory.
- **C4 (pre-eviction ceiling)** — the in-window baseline must beat every evicted condition.
  This is the check the pilot failed (Paris in-window rank 110,712 vs ~95,000 evicted); it is
  the single clearest signal that the measurement is measuring what you think.
- **C2 (distractor)** — ≥ 10× probability ratio. Below that, RQ2 weakens to "semantic gist";
  record it, don't chase it.
- **C3 (shuffled context)** — **if this fails, message Gautam that day.** It would mean AHN is
  closer to a learned recency mechanism than to content memory, which contradicts the framing
  of the original AHN paper. The Expected-Tables doc flags it as potentially the most
  publishable result in the project.

If C1 or C4 fail, **do not proceed to steps 3–7.** Spend the remaining hours diagnosing on
GDN only; a second and third cell measured with a broken instrument is nine wasted hours.

### Step 3 — Build `04b`, the RQ3 join  ·  ~1.5 h

The insertion into Gautam's order, and the one piece of engineering nothing substitutes for.
Right now retention lives on synthetic NIAH prompts and ΔF1 lives on LongBench-E HotpotQA, so
there is no per-example key and Table 8 cannot be computed at all.

The change: run the `measure()` readout on the **same 60 LongBench-E examples** notebook 03
used, keyed by the existing `id` field, with the target token being the first token of the
gold answer. Per example, save `rank`, `p_mem`, `entropy` at each of layers 9/18/27, plus the
example's `delta_f1_fl` and `boundary_js` from step 4. Write
`04b_joined_retention_task.json`; `05` cell 16 activates the moment it exists.

Two things to decide while writing it:

- Gold answers are usually multi-token. First-token-only is the cheap choice and matches what
  the README proposes; note in the file which examples have a multi-token gold so the
  limitation is quantified rather than assumed.
- Real LongBench prompts have no controlled eviction distance. Compute the *actual* distance
  from the gold answer's position in the context — `build_niah_prompt`'s
  `window_start − needle_pos` logic generalises, but the answer span has to be located first.
  Budget most of the 1.5 h here; the forward passes themselves are ~5 minutes.

**Why now and not last:** if the gold-token target turns out not to be locatable in the
context for a usable fraction of the 60 examples, the cohort has to change — and you want to
know that before running two more cells against it, not after.

### Step 8 — Table 7  ·  0 GPU-h

### Step 9 — J-lens map stability, Table 3 check 4  ·  ~1.9 h

The one Table 3 row never run: a second fit on a disjoint 500-context `corpus_b`, then top-10
overlap against the first map. Worth the hours because **a stable map that misses top-1 is a
completely different diagnosis from an unconverged one** — and that distinction is precisely
what Gautam is being asked to rule on. If the maps agree ≥ 80%, the "structural continuation
tokens crowd the top slots" story is a property of the method, and a rank-based RQ2 criterion
is defensible. If they don't agree, the fit needs more contexts and the go/no-go is premature.

Do this *after* steps 1–7. If step 1's control battery shows clean needle/distractor
separation, the lens question may already be answered empirically and this becomes optional
rather than decisive.

location proving fiddly, or a re-run of `04` on GDN after a C1/C4 failure.
